## 맵 스크립트 구조 (2026-10-04, 첫 관찰)
- `MAPnnn.BIN` = 머리 `ED3WW MAPDATbin` + u32 **절대주소 표**(0x0020xxxx = LowRAM 0x00200000 에 통째로 적재, 파일 오프셋 = 값 − 0x200000; MAP001 37칸) + 바이트코드(FF xx 명령) + 대사(명령 안 SJIS).
- 대사 명령 예(MAP001 0x1D0E7): `FF 00 02 17` + SJIS … `0D` 줄 · `0F` 쪽 … — 앞뒤 `FF 07 00 01 00 04 00 D0 00 09 00 00 00 00` · `FF 08 00 01 00 00` 등.
- ★점프가 **정렬 안 된 u32 절대주소**로 박혀 있음(예 0x1D040: `FF 19 FD 03 00 21 D0 40`). 파일 안 «0x0020xxxx 로 읽히는 값» 분포 = 대사 구역(0x1A000‥0x1F000)에 수백 개.
- ⇒ 번역이 원문보다 길면 뒤가 밀려 이 절대주소들을 전부 고쳐야 함 → **명령 길이표(역어셈블러)** 가 필요. 원문 길이 안이면 제자리로 바로 가능.
- 다음: 머리 표 진입점부터 명령을 따라가며 FF xx 별 인자 길이 확정(0.BIN 의 스크립트 해석기 분기표에서 읽는 게 확실) → 전 맵 역어셈블·재조립 무변경 왕복 검증.

## 스크립트 해석기·역어셈블러 (2026-10-04, `tools/smops.py`·`tools/smdis.py`)
- 해석기 0.BIN(0x06004000) 0x0600FA24: 워드 [앞 바이트][op] — FD → 표 0x0600CE20(6) · FE → 0x0600D078(64) · FF → 0x0600CE38(144, 필드)/0x06038D20(다른 모드). 머리가 FD/FE/FF 아니면 오류 정지 → 길이표 검증 가능. 스크립트 포인터 전역 0x0609408C.
- 흐름: FD 00 점프 · FD 01 호출 · FD 02/05 복귀 · FD 03/04 조건 점프(6 + 조건식) — 모두 u32 절대주소(파일 + 0x200000).
  조건식(0x0600D528/D3C4): 항 = 첫 워드 위 4비트 0‥2 → 1워드, 3‥7 → 2워드; 항 사이 FFFC(AND)/FFFD(OR), 0000 끝.
- 명령 길이 = 처리 함수의 «포인터 전진량»(smops 자동 분석) + LEN_FIX(FF30 8·FF36 3이면 6 아니면 4·FF63/64/65/1F 8·FF6F/70 6·FF71/72/73 4). ★FF 65·FF 1F 인자에도 u32 절대주소.
- 문장 명령 TEXT_OPS: FF 00/01(머리 +2부터) · FF 81/87(+4부터): SJIS + 제어(01·02·09·19 +1바이트, 07 +2) … 00 → 다음 짝수 주소(맞춤 바이트는 아무 값).
- 결과: 진입점(파일 안 u32 가 가리키는 명령 머리) 따라 **명령 99,124개**, 오류는 데이터 오인 진입점뿐(FFFF 등). 추출 덩어리 14,167 중 문장 명령 밖 1,267 = 대부분 MAP000 이름·데이터 표(1,062) + 소수 미도달.
- 맵 BIN 버퍼 = LowRAM 0x200000‥0x220000(128KB, 파일 뒤는 SEGASEGA 초기화 무늬 = 빈 곳; 0x220000 부터 다른 데이터). 맵별 여유(128KB − 크기) vs 대사 바이트: 대부분 충분, **빠듯한 맵 4개**: MAP026 여유 364B/대사 4.9만 · MAP007 5.7K/4.7만 · MAP001 2.9K/1.3만 · MAP023 8K/3.5만.
- ⇒ 되넣기 = 문장 길이 바꾸고 뒤를 밀며 절대주소(명령 안 FD 00‥04·FF 65·FF 1F + 데이터 표의 스크립트 포인터) 전부 고침. ⏳데이터 표 포인터 판별(오인 0 확인)·무변경 재조립 왕복·MAP000 데이터 표·0.BIN 문자열(메뉴·아이템).

## 되넣기 방식 결정 (2026-10-04)
- `tools/smbuild.py selftest`: 모든 문장 +2바이트 후 «밀며 고치기» 재조립 → 명령 9.9만 개 전부 제자리 재해석(어긋남 0, MAP026 만 버퍼 넘침). ★그러나 머리말 표·대사 뒤 데이터 구조끼리 가리키는 포인터(맵당 150~220개)가 «데이터 대상»이라 명령 분석으로는 다 못 잡음 → **밀기 방식 폐기**.
- ✅채택: **«밀지 않는» 트램펄린** — 번역이 원래 자리에 들어가면 제자리, 넘치면 원래 자리에 `FD 00 [새 주소]`(6B 점프)만 두고 `FF xx [머리] 새 문장 00 (맞춤) FD 00 [원래 다음 명령]` 을 빈 곳에 둔다. 빈 곳 = 파일 끝‥0x20000(128KB) + 짧아진/옮긴 문장이 남긴 자리. 기존 주소는 하나도 안 바뀜. 예산 = 원래 문장 바이트 + 끝 여유 − 6×옮긴 수.
- 명령 안쪽을 가리키는 u32 후보(MAP026 28·MAP007 27)는 앞쪽 그림·데이터 구역의 우연 값(0x0021xxxx) — 트램펄린 방식엔 무관.
- ⏳남은 것: MAP000 이름·데이터 표(1,062 덩어리)·0.BIN 문자열(메뉴·아이템·장 제목) 되넣기 규칙(포인터 표 조사), 빠듯한 맵(MAP026 여유 364B) 예산 — 번역 길이 맞춰야 할 수 있음.
